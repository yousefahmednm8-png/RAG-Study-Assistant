# RAG Study Assistant

Local RAG application that answers questions from your study documents.
Upload PDF/TXT files, build a vector index, and ask questions — the app
retrieves the most relevant passages and answers with cited sources,
all running locally via Streamlit, FAISS, and Ollama.

## Features

- Upload **PDF** and **TXT** documents and build a searchable knowledge base
- Dense retrieval (`intfloat/multilingual-e5-base`) followed by
  reranking (`BAAI/bge-reranker-v2-m3`) for high-precision passage ranking
- Answers generated by a local LLM served by **Ollama**
- Every answer cites its sources (document, page, chunk)
- Real-time Streamlit UI to add/rebuild the index and ask questions

## Architecture

```
Streamlit app (app.py)
   │
   └─▶ Dense Retriever  (e5-base, top-15)     src/retrieval.py
          │
          ▼
      Reranker          (bge-reranker-v2-m3)    src/reranker.py
          │
          ▼
      Prompt Builder                             src/pipeline.py
          │
          ▼
      Ollama LLM        (chat model)            src/generation.py
          │
          ▼
      Answer + Sources
```

## Tech Stack

## Installation

Requires: **Windows**, Python 3.10+, Git, and Ollama.

```powershell
git clone <repository-url>
cd rag-study-assistant

python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

## Ollama Setup

1. Install **Ollama** from https://ollama.com.
2. Make sure the server is running (the app expects it at
   `http://localhost:11434`).
3. Check your available models:

   ```powershell
   ollama list
   ```

4. The app is configured to use the model tag `gemma4:31b-cloud`
   (default in `src/generation.py`).

   - If that tag is present in your `ollama list`, no further setup is needed.
   - If you want a different model (e.g. a fully local one):

     ```powershell
     ollama pull qwen3:8b
     ```

     then set that name in `src/generation.py`:

     ```python
     Generator(model_name="qwen3:8b")
     ```

> Note: `gemma4:31b-cloud` may be a cloud-provided model that requires
> authentication in your Ollama setup. If it is not available, use a
> locally hosted model as described above.

## Run the App

```powershell
.venv\Scripts\activate
streamlit run app.py
```

Open http://localhost:8513 (or the URL Streamlit prints), upload a
PDF/TXT via the sidebar, and click **Build Knowledge Base**, then ask
questions in the main area.

## Run the Tests

```powershell
.venv\Scripts\activate
python -m pytest -q
```

## Vector Index

- A prebuilt index (built from the included study-guide PDF) is committed
  under `data/vector_store/` — the app loads it automatically, so you can
  ask questions right away without building anything.
- To build or replace the index yourself: upload PDF/TXT files in the app
  and click **Build Knowledge Base** (this replaces the previous index).
- Ingestion runs in `src/pipeline.py` (`index_documents` → `save_index`).

## Evaluation Results

Retrieval quality measured on 100 questions from the included
study guide (`evaluations/evaluate.py`):

| Setup                       | Hit@1 | MRR@5 | Recall@5 |
| --------------------------- | ----- | ----- | -------- |
| Dense only                  | 0.69  | 0.820 | 0.947    |
| Dense → Reranker (top-15)   | 0.85  | 0.913 | 0.955    |

The final pipeline (dense top-15 → rerank → top-k) uses the winning
configuration. Full breakdowns in `evaluations/results/`.

## Known Limitations

- Generation requires a running Ollama server plus the configured model
  tag (`gemma4:31b-cloud` by default); embedding and reranker models are
  downloaded from Hugging Face on first run.
- Retrieval is capped at the dense top-15 candidates before reranking.
- The prebuilt index covers only the bundled study-guide PDF.
- Answers depend on the quality/relevance of your uploaded documents.
